01 / FROM MODEL TO STORAGE

One domain. A concrete result.

Describe people, courses and their relationships.
Let the compiler derive the storage structure.

school.ontologyMODEL
type Person = {
  key email: string;
  name: string;
};

type Course = {
  key code: string;
  teacher: Ref<Person>;
  students: Ref<Person>[];
};

type School = {
  people: Person[];
  courses: Course[];
};
$ ontology compile school.ontology --root School

Composite primary key: (id, value)

Three tables. Explicit keys. Referential integrity.

CREATE TABLE "t1_courses" (
  "id" bigint GENERATED ALWAYS AS IDENTITY NOT NULL,
  "code" text NOT NULL,
  "teacher" bigint NOT NULL,
  PRIMARY KEY ("id"),
  UNIQUE NULLS NOT DISTINCT ("code")
);

CREATE TABLE "t2_courses_students_items" (
  "id" bigint NOT NULL,
  "value" bigint NOT NULL,
  PRIMARY KEY ("id", "value")
);

CREATE TABLE "t3_people" (
  "id" bigint GENERATED ALWAYS AS IDENTITY NOT NULL,
  "email" text NOT NULL,
  "name" text NOT NULL,
  PRIMARY KEY ("id"),
  UNIQUE NULLS NOT DISTINCT ("email")
);

ALTER TABLE "t1_courses" ADD FOREIGN KEY ("teacher") REFERENCES "t3_people" ("id") DEFERRABLE INITIALLY DEFERRED;

ALTER TABLE "t2_courses_students_items" ADD FOREIGN KEY ("id") REFERENCES "t1_courses" ("id") DEFERRABLE INITIALLY DEFERRED;

ALTER TABLE "t2_courses_students_items" ADD FOREIGN KEY ("value") REFERENCES "t3_people" ("id") DEFERRABLE INITIALLY DEFERRED;

02 / WHAT THE MODEL KNOWS

More meaning in the source.

Inside the compiler →
01

Identity is explicit.

Declare semantic keys with key. A person's email can identify them in the model while PostgreSQL uses a storage ID internally.

key email: string;
02

Relationships have meaning.

Use Ref<Person> for shared identity. Nested values express ownership. Sets and maps keep their own semantics.

teacher: Ref<Person>;
03

Query the domain.

O-SQL follows the fields you modeled. The compiler resolves storage details and emits PostgreSQL read functions and a result query.

c.teacher.name
03 / O-SQL

The names you modeled.
The data you need.

Query courses and teachers without writing against generated table names or surrogate IDs.

Explore O-SQL →
school.osqlQUERY SOURCE
select c.code as course,
       c.teacher.name as teacher,
       (select s.name
        from c.students as s) as students
from root.courses as c

04 / GET STARTED

A file. A command.
Your schema.

Build the CLI with Nix, then compile your first ontology. The language has its own parser and semantics; no Haskell knowledge is needed to write a model.

The reference compiler is written in Haskell. Source builds are available today.

Other build options & CLI reference →
Terminal
git clone https://github.com/hyper-analysis/ontology.git
cd ontology
nix build

./result/bin/ontology check \
  examples/school.ontology --root School

./result/bin/ontology compile \
  examples/school.ontology --root School > schema.sql
Requires Nix · Linux and macOS configurations provided
